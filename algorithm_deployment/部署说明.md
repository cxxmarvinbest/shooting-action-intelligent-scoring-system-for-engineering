# RK3588 部署说明 —— 投篮动作评分系统（无界面/日志版）

> 本版已移除 PyQt5 界面，改为纯命令行 + 日志输出。分段视频、逐帧图、各项评分及
> 原始报告、豆包 AI 评语统一写入输出目录下的日志/文本/JSON 文件，便于后续 HTTP API 读取。

## 1. 盒子端目录结构（用户 linaro）

```
/home/linaro/code/intelligent_scoring_system/
├── main.py                     # 无界面/日志版入口（python3 main.py <视频>）
├── pipeline.py                 # 编排层：预处理→检测跟踪→姿态→特征→分段→可视化
├── config.py                   # 全局配置（路径/阈值/描黑边参数）
├── scoring.py                  # 评分引擎（与 PC 版一致）
├── llm_api.py                  # 豆包 API 评语（与 PC 版一致）
├── requirements.txt            # Python 依赖清单
├── common/
│   └── rknn_utils.py           # 共用 RKNN/YOLOv8 底层（DFL解码/NMS/letterbox/_RKNNBase）
├── tracker/                    # 目标检测模块
│   ├── det_model.py            # 检测模型 RKNNDetModel（0=player, 1=ball）
│   ├── preprocess.py           # 描黑边预处理（1920x1080 -> 544x960）
│   └── target_selector.py      # 主球员筛选 + 篮球过滤
├── pose_estimate/              # 姿态估计模块
│   ├── pose_model.py           # 姿态模型 RKNNPoseModel（17 关键点）
│   └── pose_feature.py         # 关节角度/左右侧/关键特征提取
├── weights/                    # 两个 .rknn 模型
│   ├── best.rknn               # 自训练检测模型（0=player, 1=ball）
│   └── yolov8n-pose_int8.rknn  # 姿态模型（17 关键点）
├── shot_clips/                 # 标准视频 shot_1.mp4 ~ shot_29.mp4（544x960）
├── learner_videos/             # 初学者视频（RTSP 相机录制，1920x1080）
└── outputs/                    # 输出目录（自动生成，见下）
    ├── videos/                 # 分段视频 clip1_squat.mp4 / clip2_release.mp4
    ├── frames/                 # 逐帧图 frame_0000.jpg ...
    ├── scoring_*.log           # 处理日志
    ├── report_*.txt            # 纯文本评分报告
    └── result_*.json           # JSON 结构化结果（供 HTTP API 读取）
```

> 运行入口固定为 `python3 main.py`，模块间使用绝对导入
> （`from tracker.det_model import ...` 等），依赖脚本目录在 sys.path 上。

## 6. 描黑边预处理说明

- 标准视频：544x960 竖屏；RTSP 相机视频：1920x1080 横屏
- 处理逻辑（`preprocess.py`）：中央裁剪 612x1080 竖幅 → 缩放至 544x960
- 标准视频尺寸已是 544x960，自动跳过预处理（零开销）
- **人物不在画面正中时**，调整裁剪窗口横向偏移（正数向右移）：
  ```bash
  LQ_CROP_X_OFFSET=80 python3 main.py <测试视频>
  ```
  或改 `config.py` 的 `CROP_X_OFFSET`

## 7. 模型输出格式约定（重要）

两个 `.rknn` 模型的真实输出（以同目录 `.onnx` 为准，后处理在 `det_model.py` / `pose_model.py` 的 `_group_outputs` 中适配）：

| 模型 | 输出路数 | 输出内容 |
|------|---------|----------|
| 检测 best.rknn | 9 | 每尺度 3 路：box_dfl(64) + cls(2, **已 sigmoid**) + objectness(1) |
| 姿态 yolov8n-pose_int8.rknn | 4 | 3 路合并输出 box_dfl(64)+cls(1)（raw）+ 1 路已解码关键点 [1,17,3,8400] |

要点：
- 检测模型多出的 `objectness`(1 通道) 分支是冗余的（= cls 各通道之和），后处理直接忽略；
  cls 分支导出时已做 sigmoid，代码里**不能二次 sigmoid**。
- 姿态模型的 box 与 cls 是**合并**在 65 通道里的（前 64 是 box，末 1 是 cls）；
  关键点是**已解码**的（x/y 为输入图坐标、conf 已 sigmoid），无需再做 `kps_process`。
- 模型输入 640x640，由 `_RKNNBase` 构造参数 `model_w/model_h` 显式指定（默认 640x640）；
  RKNNLite 无 `get_model_attr`，不能在板端自动读取。
- rknn_lite 输出布局统一（NHWC 或 NCHW），`as_nchw` 用 box 分支（64/65 通道）自动判定并转换。

> 若换用不同导出方式的模型，先在盒子上打印 `self.rknn.inference()` 返回的各张量 shape，
> 再据此调整 `det_model.py` / `pose_model.py` 的 `_group_outputs`。

## 8. 常见问题排查

| 现象 | 排查方向 |
|------|---------|
| load_rknn 返回非 0 | 模型文件损坏/路径错；rknn 与 lite2 版本不匹配 |
| init_runtime 失败 | NPU 驱动/固件版本与 toolkit 不匹配，升级固件 |
| 检测不到人/球 | 先用板子上 rknn_model_zoo 官方 demo 单独验证模型；再查置信度阈值 |
| 评分全为默认 180° | 姿态模型无输出 → 查 pose 模型的 kps 分支解码 |
| 豆包评语失败 | 检查盒子外网连通性；不影响其他评分项 |
| 日志报 import 缺失 | 用第 3 节命令检查依赖，按 3.3 补齐 |
